# 은혜의 하루 · Christian Planner

컴퓨터와 모바일에서 함께 사용하는 개인용 크리스찬 플래너 PWA입니다. 할 일·시간표·묵상·기도·메모를 기록하고, Supabase 계정으로 로그인하면 기기 간에 항목별로 동기화됩니다.

## 최신 버전

| 파일 | 설명 |
|------|------|
| **`index.html` + `planner.html`** | **버전 8.3.1** — 설치형 PWA, 항목별 실시간 동기화, 오프라인 병합, 유실·오삭제 방지 동기화 규칙 |
| `hamin_planner_ver6.3.html` | 동기화 전 단일 HTML 보존본 |
| `hamin_planner_ver6.2.html` | 메모·스냅샷 기능 |
| `hamin_planner_ver6.html` | 시간표·사이드바 개선 |
| `hamin_planner_ver5.html` | ver4 TimeBlocks 통합 |
| `hamin_planner_ver4.html` | 주간 프로젝트·TimeBlocks |
| `hamin_planner_ver1.html` ~ `ver3.2` | 이전 버전 (참고용) |

## 사용 방법

1. `https://hkimkr.github.io/christian-planner/`에 접속합니다.
2. 오른쪽 위 `클라우드 로그인`에서 같은 계정으로 로그인합니다.
3. 모바일에서는 브라우저 메뉴의 `홈 화면에 추가` 또는 `앱 설치`를 사용합니다.
4. 모든 변경은 기기에 먼저 자동 저장되고, 연결되면 Supabase에 동기화됩니다.

## 주요 기능 (버전 8)

- **오늘** — 할 일, 시간 계획(드래그·5분 단위), 신앙 리듬, 묵상, 감사, 오늘의 기도 제목, 암송 구절
- **주간 모아보기** — 신앙 목표, 요일별 체크, 주간 기도·묵상 모아보기
- **월간** — 달력 + QT·통독 요약
- **메모** — 스크래치패드 + 포스트잇 스냅샷
- **기도 노트** — 사람·공동체별 중보기도, 긴급 표시, 상세 내용, 모바일 순서 변경
- **사이드바** — 미니 주간 달력, 이번 주 프로젝트·할 일, 메모장, 데이터 백업
- **클라우드 동기화** — 항목별 저장, 오프라인 대기열, 최신 수정 우선 병합, 실시간 수신

## 동기화 규칙 (버전 8.3.1)

여러 기기·브라우저·탭에서 동시에 써도 내용이 사라지지 않도록, 아래 규칙을 지킵니다.

1. **작성한 것은 버리지 않는다.** 화면이 보낸 스냅샷은 어떤 경우에도 폐기되지 않습니다.
   클라우드 내용을 화면에 반영하는 동안 들어온 스냅샷은 잠시 보류했다가, 반영 확인
   응답이 오거나 1.5초가 지나면 반드시 처리합니다.
2. **빈 값은 내용을 이기지 못한다.** 항목별로 병합하며, 비어 있거나 기본값인 필드는
   내용이 있는 기존 값을 덮어쓰지 못합니다. 시간만 최신인 빈 수정은 무시됩니다.
3. **삭제는 증거가 있어야 한다.** 스냅샷에 안 보인다는 이유만으로 지우지 않습니다.
   - 화면에 있었다가 없어진 경우에만 삭제로 봅니다. 다른 탭·기기에서 방금 만들어져
     이 탭 화면에 아직 없던 항목은 삭제 대상이 아닙니다.
   - 할 일·감사·시간블록·주간 과제·기도 항목은 그 날짜/주/기도 그룹이 스냅샷에 함께
     있을 때만 삭제됩니다.
   - 불확실한 스냅샷(위 1번의 보류분, 다른 탭이 쓴 localStorage를 읽은 경우 등)은
     추가·수정만 하고 삭제는 하지 않습니다.
4. **지운 것은 되살아나지 않는다.** 클라우드에 삭제 기록이 있는 항목은 되살리지 않습니다.
   다만 이 기기가 클라우드에 마지막으로 반영한 내용과 로컬이 **다를 때**는, 기존 항목의
   수정(할 일 문구 변경 등)도 버리지 않고 내용 기준으로 합친 뒤 다시 올립니다.
   이때 이미 클라우드에 있는 항목을 덮어쓰려면 이 기기가 그 항목의 클라우드 기록보다
   **나중에** 로컬을 쓴 증거가 있어야 합니다. 며칠 전 상태를 들고 있던 기기가 재접속해도
   최신 클라우드를 되돌리지 못합니다.
   이 증거는 **실제 편집**만 남깁니다. 전용 키(`…-user-edited-at`)에 따로 적으며, 페이지를
   여는 것이나 클라우드 내용을 이 기기에 반영하는 것은 편집이 아니므로 시각을 찍지
   않습니다. 이 키가 없는 기기(옛 버전에서 올라온 경우)는 편집 기록 없음으로 봅니다.
   올리지 못한 편집은 대기열에 남아 있으므로 이렇게 보수적으로 봐도 잃는 것이 없습니다.
   또한 조회가 0행이라는 사실만으로는 이 기기의 스냅샷을 클라우드 진실로 올리지 않습니다.
   이 기기가 전에 클라우드 행을 받아둔 적이 있으면 0행은 잘린 응답이나 세션 문제로 보고,
   그 외에는 행 수를 따로 세어 0임을 확인합니다. 확인되지 않으면 업로드를 보류합니다
   ("클라우드 확인 불가, 업로드 보류"). 옛 단일 행 저장소 마이그레이션도 같은 조건을
   따릅니다.
5. **같은 브라우저의 탭끼리 즉시 반영된다.** 탭마다 별도 동기화 주체를 갖고
   BroadcastChannel로 서로의 변경을 바로 병합합니다.
6. **오프라인 작업은 큐에 남는다.** 변경분은 IndexedDB 대기열에 쌓여 새로고침·종료
   후에도 남고, 서버 저장이 확인된 뒤에만 대기열에서 제거합니다.
7. **클라우드는 끝까지 읽는다.** 항목이 많아도 한 번의 응답 한도(1000행)에서 잘리지 않도록
   모든 페이지를 읽습니다. 잘린 조회는 남은 항목을 "클라우드에 없던 것"으로 오인해
   이 기기의 오래된 사본을 덮어쓸 수 있습니다.

기존 전체 JSON 데이터는 최초 연결 때 항목별 레코드로 복사하고 `planner_data`에는
백업으로 유지합니다.

규칙 회귀 테스트: `node tests/sync-rules.test.js`

## 릴리스

- `v8.3.1`: 남아 있던 두 가지 데이터 손실 경로 차단 — 오래된 사본 판정(규칙 4) 증거를 실제 편집만 쓰는 전용 키(`…-user-edited-at`)로 분리하고 저장본과 같은 in-flight 스냅샷은 증거로 인정하지 않음(기존 키는 클라우드 반영 때도 찍혀 증거가 될 수 없었음), 조회가 0행일 때 이 기기 스냅샷을 클라우드로 올리기 전에 신뢰 조건 요구(캐시에 클라우드 행이 있으면 금지, 그 외에는 행 수 조회로 0임을 확인, 확인 실패 시 "클라우드 확인 불가, 업로드 보류"; 옛 저장소 마이그레이션도 동일)
- `v8.3.0`: 며칠 전 상태로 되돌아가던 문제 수정 — 클라우드 조회가 1000행에서 잘려 남은 항목이 "클라우드에 없는 것"으로 오인되던 문제(전체 페이지 조회로 수정), 오래된 로컬 스냅샷이 최신 클라우드를 덮어쓰던 문제(이 기기가 해당 항목을 클라우드보다 나중에 고쳤을 때만 덮어쓰기 허용)
- `v8.2.3`: App 상태 선언의 문법 오류로 플래너가 빈 화면이 되던 문제 수정
- `v8.2.2`: 삭제한 항목이 새로고침 후 되살아나던 문제 수정 (최신 삭제 기록 우선, 캐시된 삭제를 로컬 스냅샷으로 되살리지 않음)
- `v8.2.1`: 입력 중이던 수정이 새로고침 후에도 유지되도록 내용 기준 병합 추가, 기기/클라우드 저장 상태 구분 표시
- `v8.2.0`: 노트 앱의 데이터 보호 동기화 규칙 이식 (유실·빈 값 덮어쓰기·오삭제 방지), 규칙 회귀 테스트 추가

## 기술 스택

- 정적 HTML + React 18 (CDN) + Babel standalone
- 기기 저장: `localStorage` + IndexedDB 오프라인 대기열
- 클라우드: Supabase Auth, PostgreSQL, RLS, Realtime
- 배포: GitHub Pages + PWA Service Worker
